# korail — KTX-A 예매 정보 → .env 반영

사용자가 자연어로 출발일 / 출발-도착역 / 열차번호 / 출발시간 같은 KTX 예매 조건을 말하면,
`c:\Users\kimghw\srt_watcher-main\.env` 의 `KTXA_*` 값을 그에 맞게 수정한다.

대화 형식이 깨져 있어도 (예: "아. 그게 티켓이 없어요?", "13:38 분이던가") 그 안의
**실제 정보**만 뽑아내서 반영하는 게 핵심.

## 추출 대상 → 매핑

| 사용자가 말한 것 | .env 키 | 형식 / 비고 |
|---|---|---|
| 날짜 ("5월 25일", "2026-05-25", "내일") | `KTXA_DATE` | `YYYY-MM-DD`. 연도가 없으면 `currentDate`(시스템 컨텍스트의 today) 기준으로 가장 가까운 미래 날짜로 추정 |
| 출발역 ("경주에서", "출발 경주") | `KTXA_ORIGIN` | 한글 역명 그대로. 따옴표 없이 |
| 도착역 ("오송으로", "→ 오송") | `KTXA_DEST` | 한글 역명 그대로 |
| 출발시간 ("13:38", "오후 1시 38분") | `KTXA_TIMES` | `HH:MM`. 여러 개면 콤마로 (예: `13:38,14:05`) |
| 시간 범위 ("13~14시 사이") | `KTXA_TIME_WINDOW` | `HH:MM,HH:MM`. 명시 안 했고 단일 시간만 있으면 **그 시간 기준 ±30분 정도로 자동 설정** (예: 13:38 → `13:00,14:00`) |
| 열차번호 ("034 열차", "KTX 034") | (env 키 없음) | 현재 워처는 시간 기준으로 매칭함. 열차번호는 사용자 확인용으로만 보여주고, 같은 출발시간이 있는 KTX가 그 열차임을 안내 |
| 인원 ("2명", "어른 2") | `KTXA_PASSENGERS` | 정수 |
| 좌석등급 ("특실", "일반실") | `KTXA_SEAT_CLASS` | "일반실" 또는 "특실" |

## 절차

1. **사용자 메시지에서 추출**: 위 표대로 토큰을 뽑는다. 모르겠는 항목은 건드리지 말 것 (기존 값 유지).
2. **시간만 있고 윈도우가 없으면** `KTXA_TIME_WINDOW` 를 시간 기준 ±30분(시 단위 반올림)으로 자동 채운다. 사용자가 한 번이라도 `KTXA_TIME_WINDOW` 를 명시했으면 그대로.
3. `.env` 를 `Edit` 으로 in-place 수정. **다른 키 (SRT_*, PAY_*, TEAMS_*, AZURE_* 등) 는 절대 건드리지 않는다.**
4. 변경 후 한 줄 요약을 사용자에게 보여준다:
   `KTXA: 2026-05-25  경주 → 오송  13:38  (window 13:00–14:00)  train#034`
5. 열차번호가 있었으면 그 번호도 요약에 포함. 없으면 생략.

## 모호한 경우 가드

- 날짜가 과거면 (예: 오늘이 5/14인데 "5월 13일") **연도를 +1 해서 미래로** 잡지 말고, 그대로 두되 사용자에게 "과거 날짜인데 맞나요?" 한 줄만 확인.
- 출발/도착이 한 쪽만 있으면 다른 쪽은 기존 값 유지. 둘 다 누락이면 변경하지 말고 묻기.
- 시간이 `HH:MM` 으로 안 떨어지면 (예: "오후 1시쯤") `HH:00` 또는 가장 그럴듯한 분으로 정규화하고 어떻게 정규화했는지 한 줄로 알린다.
- 사용자 발화에 "취소", "삭제", "지워" 가 있으면 `.env` 를 수정하지 말고 무엇을 지울지 다시 묻기.

## 예시

입력:
> 5월 25일 경주에서 오송 034 열차 13:38

수정:
```
KTXA_ORIGIN=경주
KTXA_DEST=오송
KTXA_DATE=2026-05-25
KTXA_TIMES=13:38
KTXA_TIME_WINDOW=13:00,14:00
```

응답:
> KTXA: 2026-05-25 경주 → 오송 13:38 (window 13:00–14:00) — KTX 034 열차

## 하지 말 것

- `.env` 안의 SRT_* / PAY_* / TEAMS_* / AZURE_* / `KTXA_USER` / `KTXA_PASS` 같은 자격/결제/알림 정보는 절대 수정 금지. 새 키 추가도 금지.
- 사용자가 명시한 값을 임의로 "더 안전한" 값으로 바꾸지 말 것 (예: 사용자가 13:38 이라고 했는데 13:30으로 라운딩하지 말 것).
- `.env.share` 는 건드리지 않는다 (공유용 템플릿).
